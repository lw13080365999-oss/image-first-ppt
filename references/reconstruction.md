# 从设计图重建可编辑 PPT

设计阶段已经完成页面的美术构图。本阶段依照设计图构建真实 PPT 对象，文字、数据和公式从准确内容源读取。目标是保留设计的视觉层级与构图，同时让用户实际修改约定的组件。

## 三份共同输入

同时读取，不以任意一份替代另外两份：

1. **内容源与项目契约**：`deck.json` 中的标题、`texts`、`formulas`、`tables`、`charts`、`required_assets`、来源与编辑要求。
2. **当前设计图**：本页最终采用的设计版本；实际查看图片，理解构图、层级、对齐、留白、色彩与素材边界。
3. **对象映射**：`slides/<slide_id>/objects.json`，将页面区域对应到源内容与预计创建的对象类型，记录几何范围和最终对象标识。具体格式见 [project-contract.md](project-contract.md)。

先盘点可见组件并建立映射，再制作本页。映射需要覆盖标题、正文、标签、图例、单位、公式、箭头、图片、脚注等实际组件；不要为了提高对象数量，把一个自然组件拆成大量无意义的小块。

文案不能从设计图重新 OCR 后覆盖准确源文。只有图片是唯一来源时，才使用视觉转录/OCR并逐项核验；不能猜测看不清的公式、数字或标签。图像中的错误文字不具有优先权。

## 根据内容类型选择对象

| 内容 | 默认重建方式 | 必须核实 |
|---|---|---|
| 标题、正文、图例与标签 | 原生文本框，保留必要的富文本样式 | 文字正确、可见且可编辑，换行与边界合理 |
| 表格 | 默认原生表格；只有已接受非原生替代时，特殊版式才用有语义的可编辑文本与线条组合，并准确标注其对象形式 | 行列、合并关系、数值、单位和表头对应；不能把组合图形记作已满足原生表格要求 |
| 有完整源数据的图表 | 生成带源数据的原生图表，或在用户要求下使用可编辑图形 | 数据系列、类别、坐标轴、基线、尺度与图例一致 |
| 只有原始图像的证据图表 | 使用原文件图片，按证据保留 | 不捏造数据，不声称数据系列可编辑 |
| 流程、架构与关系图 | 原生形状、文本和连接线，并按语义适当分组 | 节点、方向、标签与关系正确；线条不穿过关键文案 |
| 照片、纹理、复杂插画 | 独立图片素材 | 清晰度、裁切和比例；文字/关键数据不得随背景一起固化 |
| 数学公式 | 依据编辑要求选择原生公式或显示用矢量素材 | 见下一节；外观清晰不等于公式可编辑 |

对每页应用实际的 `requirements`。若用户要求某组件可编辑，而工具不支持，应明确记录该项未满足；不要把图片放入同名对象就算通过。

## 公式的可编辑性与显示方式

优先使用工具与目标软件实际支持的原生 OfficeMath/OMML 公式对象，保留原公式源码。先在代表性公式上验证创建、保存、重新打开与编辑行为，再应用于整稿；不能仅凭所用库宣称支持就认定成功。

需要区分：

- **OfficeMath 公式对象**：结构被正确保存，目标软件中能进入公式编辑，才可报告为公式可编辑。
- **SVG、EMF 或其他矢量公式**：可以清晰缩放，但通常是图形，不因此成为可编辑数学结构。
- **轮廓化的字形**：可以避免部分字体依赖，但语义和文字编辑能力降低，不得标成可编辑公式。
- **普通文本拼接上下标**：只适合本身就简单的表达式；不用于伪装复杂分式、矩阵或多行推导的原生可编辑性。

若 `editable_formulas` 或某公式的 `editable` 为真，显示用 SVG 不能悄悄充当合格替代。保留设计与源码、记录限制，并在必要时请用户选择可接受的降级；已有明确授权的替代方式可直接执行并如实记录。

无论使用何种方式，都检查项、括号、上下标、希腊字母、运算符、矩阵行列与编号。不要为了消除缺字方框而删除符号、改写公式或把真实方框算符误当错误。

## 分离素材，避免假编辑

设计图用于还原参照，不作为含全部信息的底图，再叠加不可见、离页或被遮挡的“可编辑”文字。也不要用白色矩形挡住旧文字后放新文字，造成设计稿残留、重复内容或换背景即暴露的问题。

准备素材时按需求选择：

- 本来就没有文案的背景、照片、插画，可裁切为独立素材，检查边缘和清晰度。
- 文案与纹理混合时，使用可用的图片编辑能力生成干净底图，并查看是否残留笔画或破坏主体；记录它对应的设计版本。
- 对复杂插画另行生成或提取独立版本，保持主体、色调、位置与整体构图。透明背景仅在实际能力支持时使用，不能用棋盘格假装透明。
- 单色背景、简单线条与必要几何结构可在重建中使用原生对象。重建允许程序化放置对象，不等于让程序重新决定整页美术设计。
- 原始证据图、标志和界面截图回插已登记的原文件，保持比例与必要标签。不要从经过生成模型改写的设计图里抠出它们当成原始证据。

如果无法分离某项素材而保持关键内容正确，应记录具体限制并修复该区域或调整对应设计。不能静默退回整页截图交付。

## 可复用重建提示

```text
根据这张设计图重建可编辑 PPT 页面。

页面 ID：{slide_id}
画布：{项目契约 canvas}
准确内容与编辑要求：{本页在 deck.json 中的完整记录及相关 requirements}
原始素材：{required_assets 对应文件、用途与来源}
设计参考：{本页设计版本与风格规则}
对象映射：{本页 objects.json，初始可为空但必须在制作时补齐}

设计图决定视觉位置、配色、层级、留白和构图。
准确内容源决定全部文字、数据、公式和关系；不要按图重写这些内容。
先盘点可见组件，逐项关联源内容，选择合适的真实对象类型。
标题正文必须是可见、可修改的文本；表格、图表、关键结构按编辑要求创建。
数据图表从源数据生成，必须保留系列、单位、标签和轴语义。
公式按源码恢复，区分可编辑数学对象与显示用矢量图片。
复杂插画和纹理可以保留图片，但要从文字与证据中分离。
不要把含正文的整页设计图当底图，再叠放隐藏的编辑对象。

保留原设计的视觉重心和布局，不在本阶段套用新的默认模板。
完成后保存实际对象标识与映射，并渲染本页检查。
若某项能力不能实现，报告具体项与已验证限制，不假称已完成。
```

## 修改与检查交接

先做代表页的真实重建与渲染，暴露对象、字体和公式支持问题后再批量应用相同方法。使用当前环境中实际可用的 PPT 创建库或编辑工具；不要把某个库或接口写成虚构能力。输出 PPT 的路径、对象 ID 和版本应与项目契约对应。

仅改小段文字时，可直接修改对应对象并检查换行和相邻组件；不必重生整页图片。改变主视觉、全局风格或主要结构时，先更新受影响的设计版本，再重建对应页面。原始内容和来源映射始终保留。

制作结束读取 [quality-assurance.md](quality-assurance.md)。
