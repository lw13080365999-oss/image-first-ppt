# 风格选择与一致性

在选择视觉方向、准备整页图片提示或处理全局风格修改时读本文件。默认自动选择，不为普通任务增加风格审批。用户要求浏览时，展示 [风格总览](../assets/styles/gallery.html) 或相应三联示意图，让其按编号或 ID 选择。

## 1. 资产性质与使用边界

[风格目录](../assets/styles/catalog.json) 提供 8 种视觉系统，每种都有封面、正文、数据页的三联 SVG 标本。所有标本使用同一组虚构内容和数据，只用于公平比较构图、层级与视觉语言。它们由程序绘制，是设计示意，**不是 image 模型生成或实测的最终效果，也不是自动套用的 PPT 模板**。

总览和单张图均明确标记示意性质；不把其中标题、数字、研究结论或来源字样带进用户稿。可将单张示意图作为图片模型的风格/构图参考，其余页面仍由模型依据实际内容设计。图片工具不接受 SVG 时，先用实际可用字体将所选标本渲染成其支持的 PNG/JPEG，再作为参考输入；这是格式转换，不是图片模型生图。不要用这些 SVG 代替当前任务应调用的图片模型。

## 2. 自动选择与用户覆盖

结合沟通任务、阅读方式、证据类型、观看距离、品牌、目标软件和用户参考，而不是仅按行业关键词选择。用户明确的参考图、品牌和字体要求优先；如果仅给配色，就保留其他维度的设计判断。

| 编号 / ID | 风格 | 构图与表达差异 | 适合的主要任务 |
|---|---|---|---|
| 01 `business-clear` | 清晰商务 | 开放式对齐、图文非对称分区、清楚的流程和比较，低装饰 | 通用报告、方案、产品说明 |
| 02 `editorial` | 杂志编辑 | 衬线/无衬线角色对比、跨栏引语、非均分栏、细线组织 | 阅读型分析、故事案例、文化介绍 |
| 03 `swiss-minimal` | 瑞士网格 | 少量大平面、精确网格、显著留白、超大数字和非对称轴线 | 简洁演讲、设计介绍、观点展示 |
| 04 `dark-tech` | 暗色科技 | 深底光场、稀疏网格、路径或局部发光、明暗层级 | 技术流程、产品演示、数字系统 |
| 05 `academic` | 学术证据 | 证据优先、清楚图题、克制标注、准确轴线与公式空间 | 研究报告、方法解释、数据讨论 |
| 06 `warm-teaching` | 温暖教学 | 柔和纸面、友好插画、编号路径、概念分步展开 | 教学、培训、科普与入门讲解 |
| 07 `creative-poster` | 创意海报 | 大字、剪切平面、强比例与对角节奏，少量有意破格 | 发布、创意提案、活动与视觉展示 |
| 08 `data-journalism` | 数据新闻 | 注释主导、横向比较、微型图、紧凑层级与来源行 | 数据简报、事实说明、趋势分析 |

不因选了某种风格就改变事实、论述结构或对象的可编辑要求。学术可以用杂志式留白，商务也可采用数据新闻构图；任务适配优先于标签。用户没有偏好时，`business-clear` 是可用的通用起点，不是对所有材料强制套用的默认模板。

## 3. 把风格落实为可执行参数

从 catalog 读取当前风格，不加载全部风格的完整提示。每套稿保留一份一致的视觉规则：

- 色彩角色：背景/表面、正文、次要文字、主色、强调与真实状态颜色，给出明确色值。
- 字体角色：中文与拉丁文标题/正文/注释的具体可用字体，字重与层级。
- 空间与构图：边距、对齐轴、留白、图像占比、章节转场与信息密度。
- 图形语言：边角、线条、分隔、纹理、插画质感与允许的层次。
- 语义约束：流程方向、比较基线、数据编码、图题和来源位置。

这些值是当前项目规则，不是对后续所有项目的永久设置。颜色编码辅以文字、线型或符号，避免仅靠颜色表达类别/状态。复杂照片可以自然带有额外颜色；不为统一色板篡改证据原图。

## 4. 中文与字体映射

catalog 提供的是字体候选和性格要求，**不是字体已安装或已嵌入的保证**。在制作本机预览和最终 PPT 前，查询实际可用字体，并按目标使用环境确认兼容性。标本不捆绑字体文件，也不依赖网络字体。

- 无衬线中文可在已安装的苹方、黑体、微软雅黑或 Noto Sans CJK SC 中选；拉丁字可选实际可用的 Arial、Helvetica、Aptos 或 Noto Sans。
- 衬线中文可在宋体、宋体简、Noto Serif CJK SC 等中选；拉丁字可用 Georgia、Times New Roman 或 Noto Serif。
- 标本优先使用本机可用的 `Heiti SC` / `Songti SC` 与 Arial / Georgia，并给出跨系统回退。实际制作应重新解析，不能照搬当前机器的结果。
- 数学字体另行验证；不能因为中文字形正常，就断言希腊字母、特殊算子和公式对象也兼容。

为当前稿记录确切映射及必要替代。检查标题、正文、数字、常用中文、特殊符号和实际公式的字形覆盖；系统自动回退可能改变宽度与换行，因此最终渲染仍须核对。字体是设计图与重建的重要一致性条件，无法使用图中的字体时选接近字形并重排，不能只换字体名称就视为完成。

## 5. 给图片设计阶段的风格块

由当前项目和当前 style 条目合成短块，而不是把整份规则重复给每页：

```text
视觉方向：<风格 ID 与本项目的具体表达>
色彩角色：<明确色值、主次与语义用途>
字体性格：<标题/正文/注释的形态、字重和层级；中文清晰>
构图语言：<本风格的空间组织、图文关系、线条与留白>
图像质感：<插画/照片/纹理与层次；不要改变原始证据>
整套不变量：<必要的身份、配色、字体角色、来源规则>
参考图角色：风格示意，仅供视觉语言参考，不复制示例内容
```

在此基础上另加当前页的准确文案、源数据/公式、素材、真实关系和构图建议。例图主要指导风格与可用布局词汇，不要求每页复制封面、三栏或同一图形。字体性格可先指导 image 设计，精确字体和可编辑字号在重建时匹配。

## 6. 重建与修改

整页 image 图是视觉依据。程序化原生文本、形状、表格、图表与公式对象用于**重建**，允许且必要；“由 image 负责设计”不能误读成整个流程禁止程序布局。禁止的是用本地样式标本或普通程序模板冒充已完成的图片模型设计。

局部修改优先保留其他页的视觉身份。全局字体、配色或风格变化时，更新视觉规则，并追踪受影响的设计图、插画、背景、原生对象及渲染。照片/生成图里烘焙的旧颜色不会因修改主题色而自动改变；需要时定向重生或编辑。最终以真实 PPT 渲染检查一致性，不能承诺与示意图或设计图逐像素相同。
